# Multi-level code-change visualization — research findings (2 rounds, 2026-09-19)

## Verdict
Nothing gives a human a clickable architecture-level DELTA with drill-down to the text diff,
for Kotlin/JVM + Python + TypeScript. Closest single tool: AppMap (unverified). Best path: compose.

## UNVERIFIED (primary-source extraction, verification budget exhausted — treat as leads)

1. AppMap — `appmap compare` emits per changed unit BOTH a line-level source diff AND a link to a
   computed sequence-diagram diff, in the same report record (ReportFieldCalculator does both in one
   loop). Standalone `appmap sequence-diagram-diff base head` renders the diagram delta as PlantUML.
   Java agent lists Kotlin. BUT: needs runtime recording (test execution) at BOTH revisions;
   `--base-revision` mandatory, shells out to `git checkout` → committed refs only, no working tree;
   drill-down is --source-url / --appmap-url hyperlink templates, not an integrated pane.
   License Commons Clause + MIT (NOT permissive). v3.203.1, 2026-09-18, actively maintained.

2. sgraph (Softagram, MIT, v1.19.0 2026-09-11) — ships a REAL model differ:
   `python -m sgraph.cli.compare old.xml new.xml`, --rename-detection, -f json, git-style exit codes.
   Language-agnostic XML model. Renderers for a SINGLE model: xml_to_dot, xml_to_plantuml,
   sgraph_to_cytoscape, xml_to_graphml, xml_to_3dforcegraph.
   BUT: only shipped analyzer is PYTHON; no Java/Kotlin extractor; differ output is text/JSON only;
   git-agnostic (takes two file paths). This is the "missing middle stage" round 1 said didn't exist.

3. Softagram is NOT dead (corrects round 1) — Analyzer page names Kotlin, Python, TypeScript.
   GitHub Marketplace $19/active dev/month, 14-day trial. "Softagram Desktop" named for local viz
   but no download link/version/price. Parser ships as a CLOSED Docker image; open graph, closed parser.

4. Structurizr structurizr-component (`!components` DSL keyword) — JVM bytecode extractor via BCEL.
   Works on local uncommitted changes after compileKotlin. Kotlin plausible but UNTESTED by vendor.
   Edges only from InvokeInstruction → no field access, type sigs, annotations. Apache-2.0 monorepo
   ships NO comparator. Detailed docs gated behind paid Patreon tier.

5. LikeC4 v1.59.3 — no diff/compare/baseline command. `export json` at two refs is the building block.
   Its `validate` "drift" = stale manual LAYOUT, not code-vs-model. Drift is third-party (Erode).
   Structurizr CLI: push/pull/lock/unlock/export/merge/list/validate/inspect — no diff; `merge` is layout-only.
   jQAssistant c4-plugin: scans C4-PlantUML INTO the graph (declared-vs-code drift), never two commits.
   Sourcetrail fork (petermost): alive (2026.6), C/C++ + Java only, no Kotlin, NO diff feature.
   Log4brains: ADR→code linking is ROADMAP ONLY; v1.1.0 Dec 2024, ~21 months stale.

## The build-it pipeline
Extract → sgraph XML model (per language, per state) → sgraph ModelCompare → render delta → link nodes
to git diff anchors.
- Kotlin/JVM extractor: structurizr-component BCEL, or Sonargraph-Build baseline XML, or write one
- Python: sgraph's own analyzer
- TypeScript: dependency-cruiser + watskeburt
- Differ: sgraph ModelCompare (MIT, rename detection) ← the piece round 1 declared missing
- Renderer: sgraph converters emit dot/plantuml/cytoscape; the diff→picture join is yours to write

## Confirmed gaps (nobody ships these)
- Language-agnostic C4-L3 COMPONENT extractor
- Topology diff (added/removed nodes AND edges) rendered as a picture
- Node-in-diagram → text hunk drill-down, on a local working tree
- Plan/ADR step → the commits+files implementing it

## Method caveats
Round 2: all 20 verified claims came from angle 1 only (3 tools). Every verifier exhausted the
200/200 WebSearch budget before adversarial third-party search — evidence is vendor docs +
JetBrains YouTrack + GitHub API + decompiled plugin bytecode. Strong for NEGATIVE claims
(a vendor does not under-document what it ships), weak for efficacy.
NOT established: Sonargraph price; whether its XML exports a dependency edge list;
whether jQAssistant's ASM scanner handles Kotlin bytecode; whether IJPL-72326 (Kotlin UML
degradation, 2021) still reproduces on IDEA 2026.2.

## ROUND-1 JOURNAL MINING (claims extracted but dropped before verification — UNVERIFIED)

These were fetched from primary sources in round 1, then lost to the budget cap before the
3-vote stage. Two of them materially change the answer.

### PR Lens (coldteadotai/pr-lens) — closest hit for use case (a)
- Renders a PR as a COMPONENT-LEVEL architecture diagram ("blast radius") plus an animated
  data-flow sequence, colour-coding the delta: green new / amber changed / red removed.
- Nodes are file/module-level. No class-level view. README never says "C4".
- MIT, free for OSS, ~1,229 stars, created 2026-08-20, last push 2026-09-16 — actively maintained.
- Four shipping forms: hosted GitHub App, GitHub Action (your model key), npm CLI
  (@coldtea/pr-lens-cli), and an agent skill for Claude Code / Codex / Gemini CLI / Cursor / Copilot.
- RUNS LOCALLY before a PR exists — explicitly positioned for reviewing coding-agent output.
- LIMITS: the graph is LLM-SYNTHESIZED from the diff (Gemini default), not derived by static
  analysis — non-deterministic enough that the model renames components between runs, hence
  correction overlays in .github/pr-lens.yml to stabilise names. Fidelity to the real dependency
  structure is unverified. Drill-down goes to nested <details> sub-diagrams and message payload
  shapes, NOT to the raw text hunk. Diffs committed refs (--base <ref> --head HEAD); uncommitted
  working tree is not a documented input.

### Erode (erode.dev) — closest hit for use case (b)
- Explicitly targets this exact gap: line diffs hide structural change. Pipeline Resolve → Scan →
  Analyze → Update, producing drift findings like "frontend bypasses API Gateway with a direct
  User Service call".
- RUNS ON LOCAL UNCOMMITTED CHANGES: CLI checks unstaged, --staged, or --branch main. Also a
  GitHub Action (erode-app/erode@0) on pull_request, AND a Claude Code skill invoked during
  agent-driven coding. Local drift landed in 0.6.0, 2026-03-06 (PR-only before that).
- Substrate is C4 architecture-as-code: LikeC4 (recommended) or Structurizr DSL (experimental).
- Unit of analysis is repo/package → C4 L2 container / L3 component. Nothing at L4.
- Output is textual findings plus a PR containing DSL model edits
  ("Remove: frontend -> user_service (undeclared); Add: api_gateway -> user_service.admin_users").
  It renders NO diagrams itself — visual rendering would come from the LikeC4 tooling it writes into.
- LLM-dependent (GEMINI_API_KEY in the sample workflow; Gemini/OpenAI/Anthropic, Anthropic
  experimental), so findings carry cost and non-determinism.

### Plan/decision → diff: NOT a confirmed gap (corrects the earlier draft)
- Traycer: Verification step programmatically compares the produced implementation back against the
  original plan. Accepts LOCAL UNCOMMITTED changes as first-class planning input, alongside diffs vs
  main/branch/commit. Output = severity-tagged text (Critical/Major/Minor/Outdated), not visual.
  Ships auto-generated Mermaid diagrams OF THE PLAN's workflow, not of the delta. Plan artifact is
  file/edit granularity + prose "Architecture and approach" — no machine-readable L3/L4 structure.
- OpenSpec: MIT, 69,495 stars, last push 2026-09-18. Change = a DELTA SPEC (ADDED/MODIFIED/REMOVED
  requirements) — diffs at requirement level, above the text diff, but as Markdown prose.
  `/opsx:verify` searches the codebase for implementation evidence and reports gaps. `openspec view`
  is a terminal UI over specs/changes only. Works on a local working tree, no PR needed.
- Kiro: spec workflow writes design.md carrying architecture and sequence DIAGRAMS — the plan is
  rendered at diagram level. But the only progress surface is task status in tasks.md; no plan→diff link.
- opcode: AGPL-3.0, ~22.4k stars. Checkpoint-to-checkpoint file diff of a live Claude Code session on
  the uncommitted working tree. Plain text diff, no architecture view, no plan/decision rendering.
- Iago: MIT agent skill, ONE Mermaid diagram per PR from four fixed types. GitHub PR only (needs a
  PR number + authenticated gh + an existing /review comment). Abstains on diffs under 10 lines.
- KIT/KASTEL ADR trace-link recovery: an open THESIS OFFERING as of mid-2025, not a tool. The group
  states no standard dataset exists for ADR→artifact trace links and such links are rarely recorded.
- LikeC4 discussion #1192: model diffing is a STANDING GAP. Community proposed a declarative
  `diff { remove {...} add {...} }` block (Nov 2024) and a git-diff-coloured-diagram request (Dec 2024);
  maintainer replied once (2024-11-01) calling versioning an unwritten RFC, and never to the three
  later diff proposals through 2026-08-12.
